# Native Job Intake J3B technical acceptance

J3B adds saved-work-order preview, server PDF rendering, download and print without adding any output-side persistence. The existing J3A document model remains the only source for identifiers, headers, PO formatting, rows, statuses, dimensions and weighted page allocation.

The saved job editor blocks Work Order preview while dirty with `Save the job before printing the work order.` It never auto-saves. The preview route authorizes `jobs=view` or `jobs=use`, loads the local repository aggregate by immutable job ID and exposes the saved revision outside the printed body. The PDF route independently authorizes and reloads that saved aggregate. Revision-pinned preview/download URLs fail when the saved job changes instead of silently returning a different revision.

One server-side `pdf-lib` renderer is used by the embedded preview, attachment download and Print action. It consumes J3A pages and row groups without recalculation or repagination, wraps rather than truncates work-order content, emits compact landscape Letter pages patterned after the deployed work order, preserves continuation headers and `Page N of total` footers, reserves footer clearance, and fails rather than clipping an allocated group. Responses use the J3A filename, PDF content type, safe inline/attachment dispositions and private no-store caching.

Production detail is limited to at most three compact attached rows. Jamb/header/sill/T-bar cuts, actionable door cut-to instructions, B.P. resolved F.O. height, glass/panel units and exception text use horizontal space without printing diagnostic property dumps, divider intermediates, unchanged slab values or zero cut-downs. Complete is silent. Warning, Glass Detail Needed and Manual Override require an explicit reusable preflight acknowledgement; Blocked prevents PDF generation. The same server preflight contract is available to later J3C work without implementing email here.

Each primary row and its attached details render inside one physical bordered group. Primary cells retain header-aligned vertical divisions, while the full-width detail area has no internal column grid or separating horizontal rule. Applicable glass/sidelight/transom lines persist `includeDiagramOnWorkOrder`; new applicable selections and legacy lines with no stored value resolve enabled, explicit `false` remains disabled, and non-applicable configurations normalize disabled. Editing and duplication preserve the preference. Equivalent-line merging uses enabled when either source requests a diagram. J3A resolves the compact proportional diagram from persisted J2 geometry and places it in the saved row-group model; the PDF renderer only draws that resolved model and never recalculates geometry.

J3A prints standard nominal `6'8"` doors using width only; standard non-`6'8"` doors and all custom slabs retain both dimensions. Work-order output actions share a save-then-output decision contract: clean and read-only jobs use the saved revision directly, while a valid dirty `jobs=use` aggregate is saved before navigation and the server reloads that resulting revision. Unapplied line-editor changes fail with a specific Apply-or-cancel message rather than being silently included. Download and Print use the same revision-pinned preview and renderer flow.

J3B adds no email controls or adapter, hosted intake/storage writes, production/fulfillment/scheduling/Calendar mutation, audit write or generated-document table. J3C remains unimplemented.
